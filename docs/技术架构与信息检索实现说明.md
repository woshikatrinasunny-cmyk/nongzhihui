# 农智汇平台技术架构与信息检索实现说明

## 一、平台定位

**农智汇是一个智能化的涉农信息检索与聚合系统**，而非传统意义上的对话式智能体。平台核心价值在于：
- 打破信息孤岛，聚合分散在各政府网站、搜索引擎的涉农资源
- 提供统一的检索入口，降低农业从业者获取信息的门槛
- 通过智能排序、分类、推荐算法提升信息获取效率

---

## 二、异构数据采集与处理

### 2.1 数据来源（多平台异构数据）

我们从以下渠道实时采集涉农信息：

1. **搜索引擎聚合**
   - 百度搜索：通过 HTTP 请求抓取搜索结果页 HTML，解析标题、摘要、链接
   - Bing 搜索：同样方式抓取，补充百度未覆盖的内容
   - 关键词策略：自动添加 `site:gov.cn` 等限定，优先抓取官方来源

2. **政府网站直接爬取**（预留能力）
   - 中国政府网 (www.gov.cn)
   - 农业农村部 (www.moa.gov.cn)
   - 全国人大网 (www.npc.gov.cn)
   - 通过定时任务 + Cheerio 解析 HTML 结构化提取

3. **本地资源库**
   - 内置 25+ 条精选涉农法律、政策、技术、文化资源
   - 作为网络搜索的补充和降级方案

### 2.2 异构数据标准化处理

**核心挑战**：不同来源的数据格式、字段、质量差异巨大

**解决方案**：统一数据模型 + 多层清洗管道

```javascript
// 统一资源模型
{
  _id: '唯一标识',
  title: '标题（清洗后）',
  summary: '摘要（200字内）',
  category: '分类（law/policy/tech/culture）',
  publishTime: '发布时间（标准化为 YYYY-MM-DD）',
  source: '来源机构',
  sourceUrl: '原文链接',
  tags: ['标签数组'],
  authority: '权威性等级（official/professional/general）',
  platform: '平台标识（baidu/bing/gov）',
  viewCount: 0,
  collectCount: 0
}
```

**数据清洗流程**：
1. HTML 标签去除：`/<[^>]+>/g`
2. 特殊字符转义：`&amp;` → `&`，`&nbsp;` → 空格
3. 空白符规范化：多个空格/换行合并为单个空格
4. 智能分类：基于标题关键词（法律/政策/技术/文化）自动分类
5. 来源识别：通过域名映射到机构名称
6. 权威性判断：`.gov.cn` / `.edu.cn` 标记为官方来源
7. 去重：基于标题前 20 字符哈希去重

## 三、信息检索核心技术

### 3.1 全网聚合搜索引擎

**实现路径**：`server/services/web-search.js` + `server/services/aggregator.js`

**工作流程**：
```
用户输入关键词
    ↓
并发请求百度 + Bing（Promise.allSettled）
    ↓
HTML 解析 + 数据标准化
    ↓
结果合并 + 去重（基于标题相似度）
    ↓
智能排序（relevance/time/authority/popularity）
    ↓
返回结构化 JSON
```

**关键技术点**：
- **并发请求**：同时查询多个搜索引擎，取最快返回的结果
- **容错机制**：某个搜索引擎失败不影响整体，降级到其他来源
- **缓存策略**：30 分钟内相同查询直接返回缓存，减少爬取压力

### 3.2 搜索联想词（Suggestion）

**实现**：`server/services/suggestion.js`

- **数据结构**：Trie 树（前缀树）存储 506 个涉农关键词
- **拼音支持**：通过 `pinyin-pro` 库支持拼音首字母搜索
- **实时响应**：前端输入 100ms 防抖后请求，后端 O(m) 复杂度返回

**示例**：
- 输入 `nongye` → 返回 `['农业补贴', '农业机械', '农业保险']`
- 输入 `土地` → 返回 `['土地承包', '土地流转', '土地管理']`

### 3.3 多维度筛选引擎

**实现**：`server/services/filter.js`

支持 AND 组合的多条件筛选：
- **年份范围**：`2020-2025` 筛选发布时间
- **分类**：法律/政策/技术/文化
- **来源机构**：农业农村部、全国人大网等
- **地区**：省级、市级、县级
- **作物类型**：水稻、小麦、玉米等

**技术亮点**：动态计算每个筛选项的可用数量，避免用户选择后无结果

### 3.4 智能排序算法

**实现**：`server/services/smart-sort.js`

**四种排序模式**：

1. **综合排序（relevance）**
   - 标题完全匹配：+100 分
   - 标题包含关键词：+50 分
   - 摘要包含关键词：+20 分
   - 官方来源：+30 分
   - 浏览量/1000：动态加分

2. **时间排序（time）**
   - 按 `publishTime` 降序

3. **权威排序（authority）**
   - official（官方）> professional（专业）> general（一般）

4. **热度排序（popularity）**
   - 按 `viewCount` 降序

### 3.5 智能推荐系统

**实现**：`server/services/recommendation.js`

**推荐策略**：
1. 基于标签匹配：计算当前资源与候选资源的标签交集
2. 同分类优先：相同 category 的资源权重更高
3. 评分公式：`score = 标签匹配数 × 10 + 同分类加成 × 5`
4. 降级方案：标签推荐不足时，补充同分类热门资源

## 四、用户多元化需求兼容

### 4.1 多端适配

**Web 端（Flask）**：
- 适合桌面浏览，大屏展示
- iframe 嵌入原文，支持在线阅读
- 完整的筛选面板和高级搜索

**小程序端（微信）**：
- 移动优先，触控优化
- 纯前端模式（本地数据）+ 网络模式（API 搜索）自动切换
- 收藏、历史、反馈本地存储，无需登录

### 4.2 搜索模式灵活切换

**全网搜索模式**：
- 实时从百度+Bing 抓取最新资源
- 适合查找最新政策、突发事件

**本地资源模式**：
- 使用内置的精选资源库
- 适合网络不佳或后端离线场景
- 响应速度快（<50ms）

**自动降级**：
- 后端超时/失败 → 自动切换到本地模式
- 用户无感知，保证服务可用性

### 4.3 个性化功能

**收藏与历史**：
- 本地存储用户行为数据
- 跨会话保留，无需注册登录

**搜索历史**：
- 记录最近 10 次搜索
- 一键清空，保护隐私

**意见反馈**：
- 本地存储反馈内容
- 后续可对接后端统计分析

### 4.4 分类浏览 vs 搜索

**分类浏览**：
- 适合不明确需求的探索式查找
- 四大类目：法律法规、政策文件、农技手册、乡土文献

**关键词搜索**：
- 适合明确目标的精准查找
- 支持联想词、筛选、排序

## 六、核心优势

1. **异构数据统一**：将分散在各平台的非结构化数据标准化为统一模型
2. **实时性**：每次搜索都是实时抓取，保证信息最新
3. **智能化**：联想词、智能排序、个性化推荐提升用户体验
4. **高可用**：多级降级策略，网络/后端故障不影响基本功能
5. **多端适配**：Web + 小程序双端覆盖，满足不同场景需求

---

## 七、定位总结

**农智汇 = 智能信息检索系统 + 轻量级智能助手**

- **核心**：信息检索与聚合（搜索引擎）
- **增强**：智能推荐、联想词、分类导航（智能化辅助）
- **未来**：可扩展对接 LLM API，实现对话式问答（智能体方向）

当前阶段更偏向**垂直领域的智能搜索引擎**，而非完全的对话式智能体。但架构设计预留了智能体扩展能力（如接入 GPT API 做问答、总结、推荐解释等）。
